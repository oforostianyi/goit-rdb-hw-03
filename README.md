## Дані

Використав повний `bank-full.csv`: **45 211 рядків**, 16 ознак і цільова колонка `y`. Взяв усі записи з [офіційного архіву UCI](https://archive.ics.uci.edu/static/public/222/bank+marketing.zip), без додаткового відбору.

Вихідний CSV зберіг у `data/`: UTF-8, роздільник `;`, розмір 4 610 348 байтів. Код отримання файла є в notebook.

Автори датасету: S. Moro, P. Rita, P. Cortez (2014). DOI: [10.24432/C5K306](https://doi.org/10.24432/C5K306). Ліцензія: **CC BY 4.0**.

## Запуск у Colab

Для перевірки відкрив notebook за посиланням вище, залишив стандартне середовище **Python 3 / CPU** та обрав **«Середовище виконання → Виконати всі»**. Потім повторив запуск через **«Перезапустити сеанс і виконати всі клітинки»**.

Залежності й дані завантажуються першими клітинками. Для PostgreSQL додав два способи запуску: `pgserver` на Python 3.9–3.12 та встановлення через `apt` у новіших середовищах Colab.

## Результати

Завантажив CSV через `COPY FROM STDIN` у `hw3_bank_staging` з текстовими полями. Через `INSERT INTO ... SELECT` переніс дані в типізовану `hw3_bank_clean`.

Значення `yes/no` перетворив на `BOOLEAN`, категорії `unknown` — на `NULL`. Для балансу обрав `NUMERIC(12,2)`, а для `pdays = -1` врахував відсутність попереднього контакту.

Після очищення зберіг усі **45 211 рядків**. Точних дублікатів не знайшов. Перевірив пропуски, розподіл професій, статистику балансу та потенційні викиди за IQR. Далі виконав десять SQL-запитів із бізнес-питаннями й висновками; наприкінці описав вибір ознак та ризики витоку інформації в Reflection.
